## 1. Что вы сдаёте на защиту (весь комплект)

По ФГОС на защиту подаётся **не только текст**:
- проектная папка (титульник → паспорт → оглавление → работа → приложения);
- **продукт** — ваш бот (демонстрируете вживую, с телефона);
- презентация (10–12 слайдов);
- текст публичного выступления;
- отзыв/рецензия руководителя.

---

## 2. Титульный лист — что и в каком порядке

1. Полное название школы (по уставу).
2. По центру: **«Индивидуальный итоговый проект»**.
3. Тема — лучше формулировкой «Чат-бот для подготовки к ЕГЭ по физике в социальной сети „ВКонтакте“» (без слова «тема», через существительное, по вашему продукту).
4. Тип проекта: **практико-ориентированный (прикладной)** — вы делаете продукт.
5. Справа/блок: «Выполнил: ФИО, ученик 11 класса…», «Руководитель: ФИО, учитель информатики…».
6. Внизу: город, год.

---

## 3. Паспорт проекта (1 страница, таблица)

Это «визитка» после титульника. Обязательные ячейки:
- тема; автор; руководитель; тип проекта (прикладной);
- **продукт**: работающий VK-бот по физике + инструкция по запуску;
- **проблема**: школьникам нужен удобный бесплатный тренажёр для ЕГЭ по физике, а готовых решений в ВК мало;
- **актуальность** (1–2 строки);
- **цель** (1 фраза), **задачи** (3–5 глаголов);
- **объект/предмет** (см. ниже);
- **гипотеза**;
- **методы**;
- **этапы работы** с примерными сроками;
- **практическая значимость**.

---

## 4. Введение (1,5–2 стр.) — «начинка» по ФГОС

Пишется сверху вниз именно в этом порядке (это логика, которую проверяют):

1. **Актуальность**: статистика — физику сдают десятки тысяч (≈120–140 тыс. в год), высокий % не преодолевших порог; занятия с репетитором дороги; сайты/сборники неудобны с телефона; школьники постоянно в ВК → бот решает задачу «там, где ученик уже есть».
2. **Проблема/противоречие**: есть РешуЕГЭ, ФИПИ, куча Telegram-ботов по информатике — но **нет удобного бота по физике во ВКонтакте**, а именно там сидит аудитория.
3. **Цель** — существительным: «*разработать чат-бота во ВКонтакте…*».
4. **Задачи** — глаголами (4–6, под вашу реальную работу):
   - изучить теоретические основы чат-ботов и механизм работы VK API;
   - проанализировать существующие средства подготовки к ЕГЭ по физике;
   - спроектировать архитектуру бота (собственный обработчик запросов);
   - реализовать функционал бота на Python;
   - наполнить базу заданий и протестировать бота;
   - апробировать на одноклассниках и оценить результат.
5. **Объект**: процесс подготовки к ЕГЭ по физике (или средства взаимодействия «ВКонтакте»). **Предмет**: чат-бот как средство подготовки.
6. **Гипотеза**: «использование VK-бота позволит готовиться к ЕГЭ по физике без дополнительных затрат на репетиторов/курсы и повысит регулярность занятий» — зафиксируйте её как проверяемую.
7. **Методы**: анализ литературы и сайтов, изучение документации VK API, моделирование/проектирование, программирование, тестирование, анкетирование (соберите 10–20 ответов одноклассников).
8. **Практическая значимость** + **новизна**: ваш отличительный признак — **собственный обработчик запросов ВК** без готовых библиотек-конструкторов; ориентир на физику (аналогов почти нет).

## 5. Глава 1. Теоретическая (2 параграфа, по 4–6 стр. всего)

**1.1 Чат-боты и их применение в образовании:**
- определение чат-бота, краткая история;
- виды (по сценариям / по ИИ / командные);
- где применяются и почему удобны в обучении;
- **обзор существующих решений**: РешуЕГЭ, «Сдам ГИА», ФИПИ, существующие боты по физике/другим предметам — кратко опишите 3–5 и покажите, **чего у них нет** (мобильность, доступ из ВК, тренировка конкретных номеров КИМ).

**1.2 Технологическая платформа — «ВКонтакте» и Python:**
- почему ВК (аудитория школьников России);
- устройство сообщества: как бот получает сообщения — **Longpoll API и Callback API**, метод `messages.send`, токены сообщества и пользователя, формат событий (JSON);
- почему Python и почему **собственный обработчик запросов** (без `vk_api`/`vk-bot`): полный контроль над логикой, отсутствие лишних зависимостей, лучше для учебного проекта (это ваш исследовательский вклад).

## 6. Глава 2. Практическая (основная, 8–12 стр.)

**2.1 Проектирование:**
- техническое задание: перечень функций бота (команды start/help, меню тем, вывод заданий, проверка ответа, разбор решения, статистика);
- **сценарий работы** описать словами + схема: `сообщение → Long Poll сервер ВК → ваш обработчик (парсинг JSON) → маршрутизация по командам → ответ`. 
- спроектируйте структуру данных: база заданий (тема/номер задания/условие/ответ/разбор) — где хранится (JSON/SQLite) и почему.

**2.2 Реализация (главный блок — тут ваша «фишка»):**
- среда: Python, версия, используемые библиотеки (accept-зависимости — только стандартные + requests);
- **структура проекта с описанием каждого файла** (например: `main.py` — запуск, `vk_handler.py` — собственный обработчик, `commands.py`, `tasks/…`);
- описание **вашего обработчика запросов по шагам**: получение события, извлечение текста и user_id, распознавание команды, передача в нужный модуль, клавиатуры, обработка ошибок;
- 3–5 фрагментов кода с пояснениями (не весь код);
- почему использовали Longpoll, как храните токен и ответы.

**2.3 Тестирование и апробация (обязательно для ФГОС):**
- таблица тест-кейсов: команда → ожидаемый результат → фактический → статус;
- сколько пользователей протестировали, сколько сессий/вопросов, отзывы (процитируйте 2–3);
- изменения, внесённые по итогам тестирования;
- вывод: гипотеза подтвердилась/уточнена.

## 7. Заключение (1–1,5 стр.)

Пункт за пунктом ответите: достигнута ли цель; **решена ли каждая задача из введения** (по абзацу на задачу); подтвердилась ли гипотеза. В конце — перспективы: добавить генерацию вариантов, статистику по ошибкам пользователя, ИИ-подсказки, расширить на другие предметы.
